\section{Experimental Setup}
\label{sec:setup}

\paragraph{Models:}
The primary model is Qwen2.5-7B with bfloat16 weights, eager attention, and no quantization \citep{qwen2024}: 28 transformer layers, 28 query heads, 4 key-value heads (grouped-query attention), head dimension 128. To test generality we repeat the core protocol on Qwen2.5-1.5B (same family, weaker prior), Llama-3.1-8B, and Mistral-7B (different families, different pretraining corpora). In every case we adapt the top third of layers for both KV memory injection and the $W_{\mathrm{cons}}$ LoRA module; the adapted set is derived from each model's layer count rather than hardcoded. Before any experiment on a new architecture, a verification harness asserts three ground-truth properties of the injection path on the real model---empty-bank identity, populated-bank effect, and disable-restores-baseline---and the architecture is excluded if any check fails (none were).

\paragraph{Dataset:}
We construct a controlled benchmark of 200 synthetic facts spanning 10 templates: corporate financials, scientific discoveries, city foundings, regulatory protocols, world records, technology architectures, medical trials, sports records, album releases, and geological events. Each fact is a single sentence containing fictional entity names, specific numerical values, and contextual details. Templates are deliberately structured so that the surprising tokens (entity names like ``Nimbus Holdings'') cluster at the start of each fact, with factual content (revenue figures, dates, percentages) following. Each fact is paired with a question prompt and a list of three keywords expected in a correct answer. The dataset is generated by deterministic seeded Python code; see Annexure for the generator.

We deliberately use synthetic facts rather than natural documents to isolate single-exposure encoding from prior-knowledge confounds. Real-world facts may have been seen during pretraining, making it impossible to distinguish ``the model recalls because it learned'' from ``the model recalls because it always knew.''

\paragraph{Evaluation metrics:}
We measure three forms of recall and one preservation metric:

\textbf{Multiple-choice accuracy (MC):} for each fact, the correct keyword and three same-template distractors are presented as options A--D in a randomized order seeded by fact ID. We compute the model's logit at each option's first token following ``Answer:'' and report the fraction where the argmax matches the correct option. We also log $P(\mathrm{correct})$ and $P(\mathrm{correct} \mid \mathrm{wrong})$ via softmax over the four option-letter logits, providing a calibration view sensitive to partial encoding.

\textbf{Cloze accuracy:} the prefix of the fact text up to (but not including) the first keyword is provided as a prompt; the model generates 20 tokens; we score 1 if the keyword appears in the generation, 0 otherwise.

\textbf{Free-form delayed recall accuracy (DRA):} the fact's question prompt (e.g., ``What was Nimbus Holdings' Q3 revenue?'') is provided; the model generates 50 tokens with temperature 0.7; we compute the fraction of expected keywords appearing in the generation. The aggregate DRA is the mean across facts.

\textbf{Base capability preservation (BCP):} we measure perplexity on three held-out control texts (capital of France, water boiling temperature, Python's history) before and after each modification, and report the ratio $\mathrm{BCP} = \mathrm{PPL}_{\mathrm{after}} / \mathrm{PPL}_{\mathrm{before}}$. $\mathrm{BCP} \leq 1.05$ is the preservation threshold (no meaningful degradation); $\mathrm{BCP} > 2$ indicates substantial damage.

\paragraph{Baselines:}
The \textbf{base model} is the unmodified Qwen2.5-7B. \textbf{Naive LoRA} is a single LoRA adapter (rank 16, $\alpha=32$, applied to V/O projections of the same top-third layers as $W_{\mathrm{cons}}$) trained directly on the 200 facts via uniform-with-replacement sampling for 100 gradient steps with AdamW (lr $10^{-4}$, weight decay 0.01, batch size 32). This matches SLEEP's compute budget but applies no safety constraints. We add three reference points that bound the problem from opposite directions: \textbf{in-context injection} places the gold fact directly in the prompt with no training at all (an upper bound on what the model can do with a fact it can see); \textbf{RAG} retrieves the top-3 facts by mean-pooled embedding similarity and prepends them \citep{lewis2020retrieval}; and \textbf{EWC-only} applies the Fisher-weighted penalty to naive LoRA with none of SLEEP's other machinery, isolating how much of any preservation benefit is attributable to EWC alone.

\paragraph{Seeds and variance reporting:}
Every headline result is run across multiple random seeds, each in an independent process so that model initialization, tagging decisions, replay sampling, and MC option ordering all vary. The single-cycle pipeline and its recall/preservation metrics use five seeds (0--4) \emph{per model} and we report mean $\pm$ standard deviation throughout. The warm-up experiments use two seeds per variant per model (sixteen runs total). The ten-cycle continual-learning protocol runs three seeds on Qwen2.5-7B and two on each other model (nine run-pairs); because its seed variance turns out to be the finding rather than noise, Section~\ref{sec:multi_cycle} reports per-run trajectories rather than averages.

\paragraph{Warm-up protocol:}
The retrieval-aware warm-up (Section~\ref{sec:warmup_method}) trains on 400 passages drawn from WikiText-2, filtered to 80--400 characters and containing none of the evaluation facts. Each step samples a passage, splits it at a point drawn from the middle two quarters, writes the prefix episode into the bank, and takes one AdamW step (lr $10^{-3}$, gradient clipping 1.0) on the continuation with memory injected. We report 300-step runs; a 150-step configuration was also tested and is reported in Section~\ref{sec:results_warmup}. After warm-up the gate is frozen and the bank cleared, so evaluation begins from an empty memory exactly as in the no-warm-up condition.

\paragraph{Hyperparameters:}
All non-overridden values track the formalization defaults. We document four hyperparameter overrides applied during the empirical work, each with its empirical justification logged at the time the change was made (see the logbook entries cited in Annexure~A): $\alpha_{\mathrm{slow}} = 10^{-4}$ (precision floor under bfloat16; the $10^{-5}$ default produces zero detectable parameter movement), $\delta_{\max} = 0.01$ (model-scale-dependent; $10^{-3}$ saturates within 30 steps on 7B), KV top-$k = 64$ (must scale with episode size; episodes are $\sim 30$--40 tokens so $k=16$ retrieves only fragments), and quality-check $\mu_{\mathrm{surprise}}$ disabled (the formalization's absolute-surprise threshold suffers from a generator-discriminator gap on self-generated replays). The full hyperparameter list is given in Table~\ref{tab:hyperparams_full} of the Annexure.

\paragraph{Compute:}
Experiments run on single NVIDIA GPUs via RunPod: an RTX 5090 (32GB) for the initial single-cycle work and RTX A6000s (48GB) for the multi-seed, ten-cycle, warm-up, float32, and cross-model programmes---single precision at 7B and the full four-model matrix both require more than 32GB. Total compute for all experiments reported in this paper is approximately 25 GPU-hours, totaling roughly USD \$20 in cloud cost. Each end-to-end run (200 facts, full sleep cycle, complete evaluation suite) takes 8--15 minutes at 7--8B scale. We log every run's command line, configuration, output, and resulting metrics; these are released alongside the implementation.

\paragraph{Reproducibility:}
The implementation comprises approximately 3,500 lines of Python across six modules (tagging, prp, weights, sleep\_engine, orchestrator, evaluation), with 297 unit and integration tests. The 36-question formalization and the empirical amendments derived from it are released as a separate document to enable independent reproduction. The exact RunPod instance image, Python version, and \texttt{transformers} library version (5.7.0) are documented; \texttt{attn\_implementation=eager} is forced because the Scaled Dot-Product Attention (SDPA) path handles 4D additive masks differently and silently degrades the gating mechanism.
